# Task1

## 1. Стратегия масштабирования и отказоустойчивости

Для сервисов core-app, client-info, ins-product-aggregator и ins-comp-settlement выбрано горизонтальное масштабирование в Kubernetes.  
Для автоматического увеличения числа pod используется HPA (горизонтальное масштабирование).

Отказоустойчивость обеспечивается размещением кластера в 3 зонах доступности. При отказе одной зоны сервис остаётся доступным в остальных.

## 2. Конфигурация Kubernetes

Используется один Kubernetes-кластер, распределённый по зонам доступности A, B и D.  
В каждой зоне размещена своя node group.

## Балансировка нагрузки

Для ускорения загрузки статики используется CDN .  
Для маршрутизации используется Cloud DNS.  
Внешний трафик распределяет Application Load Balancer (балансировщик прикладного уровня).Application Load Balancer выполняет health check.

## Failover-стратегия

Если выходит из строя pod, Kubernetes перезапускает его.  
Если выходит из строя node, pod запускаются на других node.  
Если недоступна одна зона, Application Load Balancer переводит трафик в оставшиеся зоны.

Такой подход позволяет выдержать RTO (целевое время восстановления) 45 минут.

## Конфигурация базы данных

- Используется кластер PostgreSQL:
  - primary в зоне A;
  - replica в зоне B;
  - replica в зоне D.
- Для управления кластером используется Patroni.
- Patroni контролирует состояние узлов и выполняет автоматический failover при отказе primary.
- Для подключения приложения к БД используется HAProxy.
- HAProxy предоставляет единый endpoint и перенаправляет запросы на текущий primary.
- Между узлами PostgreSQL настроена репликация.
- Для резервного копирования используются:
  - WAL (Write-Ahead Log, журнал предзаписи) archive;
  - backup каждые 15 минут;
  - хранение в Object Storage.

## 3. Шардирование базы данных

Шардирование не используется.

Причина в том, что текущий объём данных составляет 50 GB, и для такой нагрузки достаточно одного кластера PostgreSQL с репликацией, резервным копированием и возможностью вертикального масштабирования.
